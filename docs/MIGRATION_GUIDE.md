# Руководство по миграции в чистовой репозиторий

## Проблема

Есть два репозитория:
- **Черновой** (этот) — полная история разработки с 220+ коммитами
- **Чистовой** (другой GitHub) — репозиторий для сдачи, загрузка только через веб-интерфейс

В чистовом репо уже есть код из ранних итераций. Нужно довести его до текущего состояния так, чтобы это выглядело как **естественная доработка**.

## Подход

Разработка разбита на **8 логических фаз**. Каждая фаза — одна загрузка через GitHub с осмысленным коммит-сообщением.

## Как использовать скрипт

### Предварительная подготовка

```bash
cd /path/to/career_copilot
```

### Шаг 1: Определите, что уже есть в чистовом репо

Посмотрите список фаз:

```bash
python3 scripts/prepare_migration.py --list-phases
```

Определите, какая фаза (или какие фазы) уже загружены в чистовой репозиторий.

### Шаг 2: Создайте пакеты для недостающих фаз

**Вариант A** — если в чистовом репо уже есть код до фазы N:

```bash
# Например, если в чистовом репо есть фазы 1–3:
python3 scripts/prepare_migration.py --base-phase 3
```

Это создаст папки с файлами для фаз 4–8 в каталоге `_migration/`.

**Вариант B** — если знаете конкретный коммит, соответствующий состоянию чистового репо:

```bash
python3 scripts/prepare_migration.py --base-commit abc1234
```

**Вариант C** — создать один «diff-пакет» (все изменения одним коммитом):

```bash
python3 scripts/prepare_migration.py --base-commit abc1234 --diff-only
```

**Вариант D** — создать полный снимок (для загрузки с нуля):

```bash
python3 scripts/prepare_migration.py --snapshot
```

### Шаг 3: Загрузите файлы в чистовой репозиторий

Для каждой фазы (в порядке номеров):

1. Откройте папку `_migration/phase_XX_.../`
2. Прочитайте `README_UPLOAD.md` — там список файлов и инструкция
3. Откройте чистовой репозиторий на GitHub
4. Нажмите **«Add file»** → **«Upload files»**
5. Перетащите файлы из папки `files/` (сохраняя структуру каталогов)
6. В поле Commit message используйте сообщение из `README_UPLOAD.md`
7. Если есть удалённые файлы — удалите их отдельно через веб-интерфейс

## Рекомендации для естественности

### Коммит-сообщения

Скрипт предлагает осмысленные коммит-сообщения на русском, привязанные к содержанию фазы.
При желании их можно скорректировать.

### Временные промежутки

- Не загружайте все фазы за 5 минут — сделайте паузы между фазами
- Фазы 1–3 (февральские) можно загрузить в один день
- Фаза 4–6 (апрельские) — через несколько дней
- Фаза 7–8 (апрель-май) — ещё через несколько дней

### Что НЕ загружать

- `package-lock.json` — генерируется автоматически
- `.git/` — не нужно
- `node_modules/`, `.venv/`, `__pycache__/` — не нужно
- `_migration/` — служебная папка скрипта

Скрипт автоматически исключает эти файлы.

### Если в чистовом репо другая структура

Если ранний код в чистовом репо структурно отличается (другие имена файлов, другая вложенность), есть два варианта:

1. **Удалить старые файлы** из чистового репо и загрузить полный снимок (`--snapshot`)
2. **Постепенно заменять**: сначала загрузить промежуточную фазу, потом следующую

## Альтернативные подходы

### Если есть доступ к git CLI для чистового репо

Можно добавить черновой репо как remote и cherry-pick/squash:

```bash
cd clean_repo
git remote add draft https://github.com/superdash777/career_buid_sysytem.git
git fetch draft
git merge --squash draft/main
git commit -m "feat: доработка проекта"
```

### Через GitHub API (для продвинутых)

GitHub API позволяет создавать коммиты программно через Contents API, что может быть автоматизировано скриптом.

### Git-format-patch

Экспорт патчей и применение в другом репо:

```bash
# В черновом:
git format-patch <base_commit>..HEAD -o patches/

# В чистовом:
git am patches/*.patch
```

Но это требует git CLI доступа к чистовому репо.
